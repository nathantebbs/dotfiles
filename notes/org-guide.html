Using This Org Setup

2026-08-12dotfiles @ 99eddb1Guide

One rule runs the whole system: capture never asks where a thing belongs. When a thought arrives you hit C-c c t, type it, hit C-c C-c, and go back to what you were doing. It lands in inbox.org and you decide what it really is later, once a week, when you can see the whole picture. Everything below is either a consequence of that rule or a key you press to act on it. If you only remember two keys, remember C-c c to put something in and C-c a d to see what to do now.

How to read this Every keybinding in this document was verified against your actual config, including the Evil layer, so what is written here is what your Emacs really does rather than what a generic tutorial assumes. Section links go to the official Org manual.

1. The daily loop

Three motions, and only the middle one is a habit you have to build.

Throughout the day
C-c c t for anything that occurs to you. Do not think about where it goes. Do not schedule it. Type the thing and finish with C-c C-c.
When deciding what to do
C-c a d. The top block is what is actually due today, the bottom block is every NEXT item across all your files. Pick from the bottom block.
At the end of something worth remembering
C-c c j to write a journal line. This is the habit that survived your last setup for two months, so it is the one most likely to stick.

Notice that nothing in the daily loop requires you to open a file. That is deliberate. Opening life.org and reading it is not a step in this system.

2. The weekly review

This is the only ritual, and the system dies without it. Pick a day. Twenty minutes.

Run C-c a r. You get three blocks.

  1. Inbox. For each item, decide what it is and press C-c C-w to refile it to its real home. If it is not worth doing, C-c C-t and mark it CANCELLED. The goal is an empty inbox, and empty is achievable because deciding is all you are doing.
  2. Waiting on. Every WAIT item. Ask whether the thing you are waiting for has arrived, and whether it is time to chase it.
  3. Stalled projects. Every ACTIVE project with no NEXT child. Each one is a project you think you are working on but have given no next action. Either give it one with C-c C-t n on a child task, or be honest and mark the project PAUSED.
Why block three matters most A stalled project is invisible everywhere else. It does not show up in the day agenda because it has no dated or NEXT item, so it silently rots. Your previous projects.org had four items sitting at BACKLOG or TESTING for months with nothing ever surfacing them. This block is the fix.

3. Your files

Seven files. The file is the only thing that says which area of life something belongs to.

Four of the seven you never have to think about placing. Only the three actionable ones receive a refile, which means refiling is the only operation in the entire system that asks you to make a judgement.

4. Capture

C-c c then one letter. A small buffer opens, you type, and C-c C-c files it. C-c C-k throws it away.

KeyWhatLands inInserted as
C-c c tTaskinbox.org* TODO
C-c c pProject ideainbox.org* IDEA
C-c c nNotenotes.org under * Unfiled**
C-c c jJournal entryjournal.org, into a date tree**** 21:43
C-c c rRecipefood.org under * Recipes**

The journal template builds the tree for you, so the first entry of the day creates * 2026, ** 2026-08 August and *** 2026-08-12 Wednesday and puts your line under it stamped with the time. You never create those headings yourself.

Inside the capture buffer, these are the only keys you need.

KeyDoes
C-c C-cFile it and close.
C-c C-kAbort and discard.
C-c C-wFile it somewhere other than the template target, right now.
C-u C-c C-cFile it and jump to it, instead of returning to your work.

Three prefixes on C-c c itself are worth knowing. C-u C-c c goes to a template's target location without capturing anything, which is a quick way to open inbox.org. C-u C-u C-c c jumps to the last thing you captured. And C-1 C-c c j prompts for a date, which is how you backdate a journal entry you forgot to write yesterday.

Manual: Capture, Capture templates, Template expansion (the %? and %<%H:%M> syntax).

5. TODO keywords

C-c C-t on a heading cycles state, and because the keywords are declared with fast-access letters you can jump straight to one: C-c C-t n sets NEXT in one motion. That is worth learning, because NEXT is the keyword the day agenda runs on.

Two independent sequences. Tasks use the first, project subtree roots use the second. Both are visible to C-c C-t, so do not be surprised that a task can be marked ACTIVE; just do not do it.

KeywordKeyMeansOn entry
TODOtNeeds doing eventually. The default resting state.nothing
NEXTnThe thing I do next. Shows in the day agenda.nothing
WAITwBlocked on someone else.prompts for a note, plus timestamp
DONEdFinished.timestamp
CANCELLEDcDeliberately not doing it.prompts for a note
IDEAiA project that might happen. Your old BACKLOG.nothing
ACTIVEaA project being worked on. Your old DEVELOPMENT.nothing
PAUSEDpReal project, deliberately stopped.prompts for a note
SHIPPEDsProject done.timestamp
DROPPEDxProject abandoned.prompts for a note

The note prompt on WAIT is the single most useful thing in this table. When you mark something WAIT, Org asks why, and the answer goes into a :LOGBOOK: drawer. In a week the question you will have is "waiting on what", and if you had not been forced to write it down the answer would be gone.

The state history lives in a drawer rather than cluttering the body, which is why your headings stay readable. C-c C-z adds a note by hand at any time. Manual: Workflow states, Fast access, Tracking state changes, Drawers.

6. Tags

C-c C-q on a heading, then the letter. The tag set is declared, so completion offers exactly these and a typo cannot quietly invent a new tag.

TagKeyFor
@homehNeeds to be at home.
@errandeNeeds to be out of the house.
@computercNeeds a machine.
@phonepA call or a text.
healthHAppointments, prescriptions, exercise.
financefMoney.
adminaPaperwork, accounts, bureaucracy.
socialsPeople.

The four @ contexts are a mutually exclusive group: setting one clears the others, because you cannot be in two places. The lower four stack freely.

Tags inherit down the tree, so a tag on a project root applies to every task inside it. To find things by tag outside the agenda, C-c / m builds a sparse tree in the current file. Manual: Tags, Setting tags, Matching tags.

7. Dates, deadlines and repeaters

This is the part most people get wrong, and your old files got it wrong too: they used DEADLINE for weekly chores, which is not what a deadline is for.

C-c C-s — SCHEDULED
I will start working on this on this date. Before that date the item is invisible in the agenda. Use it to hide things until they are relevant.
C-c C-d — DEADLINE
This must be finished by this date. Org starts warning you several days in advance and nags after it passes. Use it only when something genuinely goes wrong if you miss it.
C-c . — plain active timestamp
An appointment. It appears on that day and does not nag. This is what most calendar-like entries actually want.
C-c ! — inactive timestamp
A date written down for the record. Never appears in the agenda.

Rule of thumb: a recurring chore wants SCHEDULED, a tax return wants DEADLINE, a dentist appointment wants a plain timestamp.

Repeaters

Adding a repeater makes the date roll forward when you mark the item DONE, instead of the task disappearing. The three forms differ in a way that matters for chores.

FormOn DONE, the date moves toGood for
+1wExactly one week after the old date, even if that is in the past.Things on a fixed external cadence, like a bill.
++1wForward in one-week steps until it is in the future.Fixed cadence you sometimes skip, like a meeting.
.+1wOne week from today, whenever you actually did it.Chores. Washing sheets a week after you last washed them.

Your old chores used +1w, which is why they piled up as overdue whenever you missed a week. For those, .+1w is what you wanted.

* TODO Wash the bed sheets            :@home:
  SCHEDULED: <2026-08-16 Sun .+1w>

S-<left> and S-<right> on any date shift it by a day, which is far quicker than retyping. With the cursor on the year, month or hour, they shift that field instead. Manual: Deadlines and scheduling, Repeated tasks, Timestamps.

8. Refiling

C-c C-w on a heading moves that whole subtree somewhere else. This is how the inbox empties, and it is the one operation worth practising.

Your config shows candidates as full outline paths like life.org/Chores/Weekly, and completes them in a single step, so Vertico can match against any part of the path. Type chores and it narrows. Targets are every heading down to level three across all your agenda files, which includes work.org.

C-u C-c C-w jumps to a heading without moving anything, which is a fast way to navigate. C-c C-x C-w cuts a subtree and C-c C-x C-y pastes it, for when you want manual control. Manual: Refile and copy.

9. The two agenda views

C-c a opens the dispatcher, then d or r. Everything else in that dispatcher is Org's built-in set, which you can ignore until you want it.

C-c a d — Day

Today's scheduled items and deadlines, then a block of every NEXT item across all files. Work and personal appear together, labelled by file. This is the view you make decisions from.

C-c a r — Review

Three blocks: the whole inbox, everything WAIT, and every ACTIVE project with no NEXT child. Described in §2.

Manual: Agenda views, Dispatcher, Built-in views, Custom views.

11. Moving and restructuring

These are the keys that make Org feel like an outliner rather than a text file. All verified in Evil normal state.

KeyDoes
TABFold or unfold the subtree at point.
S-TABCycle folding for the whole file: overview, contents, all.
M-RETNew heading at the same level.
M-S-RETNew TODO heading at the same level.
M-<left> / M-<right>Promote / demote the heading one level.
M-<up> / M-<down>Move the whole subtree up / down past its siblings.

Two Evil differences zR and zM are not bound in Org buffers, so use S-TAB for whole-file folding rather than the Vim keys you may reach for. And your global M-p / M-n line-moving keys are unbound here; use M-<up> and M-<down>, which move entire subtrees and are what you actually want in an outline.

12. Links

C-c C-l inserts a link, C-c C-o follows the one at point. Linking between your own files is what turns seven files into one system, and your old setup used this well.

The durable way to link to a specific heading is to give it a CUSTOM_ID and link to that, because it survives the heading being reworded:

* TODO Renew the passport
  :PROPERTIES:
  :CUSTOM_ID: passport-renewal
  :END:

Elsewhere, in any file:
[[file:life.org::#passport-renewal][passport]]

Other forms you will use: [[https://example.com][label]] for the web, [[file:~/source/repos/dotfiles/README.md][label]] for a file, and [[*Exact heading text]] for a heading in the same file when you do not need it to be durable. Manual: Handling links, Internal links, External links.

13. Checkboxes, priorities, properties

All three you already used, so this is a refresher rather than new ground.

Checkboxes
- [ ] thing in a body, toggled with C-c C-c. Use these for the steps inside one task, and keep them out of the agenda where they would be noise. Adding [/] or [%] to the parent heading makes Org maintain a live count, which is what produced the [75%] markers in your old files.
Priorities
C-c , sets [#A], [#B] or [#C]. Worth using sparingly: if everything is [#A] the field carries no information. In practice NEXT does most of the work priorities are usually asked to do.
Properties
C-c C-x p adds an arbitrary key/value to a heading, stored in a :PROPERTIES: drawer. Good for structured facts attached to a task, the way you stored a FLIGHT_NUMBER and a LOCATION on flights.

Manual: Checkboxes, Breaking down tasks, Priorities, Properties.

14. Archiving

C-c C-x C-a on a heading moves it out of the live file. It goes to archive/<filename>_archive next to the file it came from, so archiving from life.org writes to ~/source/org/archive/life.org_archive.

Because Org expands agenda directories non-recursively, anything under archive/ is invisible to the agenda automatically. No exclusion rule maintains that; it is a property of the layout.

You do not need to archive often. DONE items are already hidden from the agenda. Archive when a file gets long enough to feel heavy. Manual: Archiving.

15. Where it lives, and git

~/source/org/                 git remote: github:vetr0s/org
  inbox.org  life.org  projects.org
  notes.org  journal.org  food.org
  archive/                    everything from the school era, plus *_archive files

~/source/work-org/            NO REMOTE, deliberately
  work.org
  archive/
Why work is a separate repo ~/source/org pushes to GitHub. Work notes, ticket numbers and internal names in a repo hosted outside the company is the kind of thing an employment agreement prohibits. ~/source/work-org has no remote at all, which is a stronger guarantee than a .gitignore entry: an ignored file silently stops being backed up, and you find out when you need it. If you ever want work backed up, give that repo a private remote rather than moving the file.

Both directories are listed in org-agenda-files, and the list is filtered so a missing directory cannot break the agenda. That means the setup still works on a machine where you have not created ~/source/work-org.

The config itself is ~/source/repos/dotfiles/.emacs.d/configs/rc-org.el. Settings there are grouped by the Org file that defines each variable rather than by topic, because Org spreads its options across org.el, org-refile.el, org-capture.el and org-agenda.el, and setting one before its own file has loaded assigns to a free variable and skips any setter.

16. Traps specific to this setup

Do not use C-c [ or C-c ]
They add and remove agenda files interactively, but org-agenda-files is computed in your config every time Org loads. Your change would be silently discarded on restart. Edit rc-org.el instead.
compile moved to C-c b
It used to be C-c c, which Org capture now owns. Mnemonic: b for build.
Do not organise the inbox in place
The moment you start adding structure inside inbox.org it becomes a second todo file, and the discipline that makes capture cheap is gone. Refile out, always.
A task marked ACTIVE will not error
Both keyword sequences are offered by C-c C-t. Nothing stops you putting a project keyword on a task, but the agenda blocks assume you have not, so a task marked ACTIVE can show up under stalled projects.
Two dotfiles machines will disagree until you commit
The archive move and the new files are staged or untracked, not committed. Until you commit and push, another machine sees the old school-era layout.

18. Reference and further reading

The official one-page key reference. Print it and keep it next to you for the first fortnight. This is the highest-value link on this page.

Short, official, and a good way to reload the basics in fifteen minutes.

Complete and genuinely well written. Also available inside Emacs with C-h i then choosing Org, which is faster than the web.

The community wiki. Where to look for workflows, agenda recipes and other people's setups once you want to go past this one.
evil-collection
The package supplying the Evil bindings in Org buffers. Read evil-collection-org.el if a key behaves unexpectedly.

Inside Emacs, C-h B lists every binding in the current buffer via Embark, which is the quickest way to answer "what does this key do here" without leaving the file.
