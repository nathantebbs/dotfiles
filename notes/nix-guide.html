Migration review

The migration is ready for daily macOS development. Homebrew is absent. The account login shell points to the Nix profile. A clean login shell resolves the managed toolchain from that profile.

Configuration map

flake.nix
Declares the pinned inputs and the macOS and Linux profiles.
flake.lock
Records exact Nixpkgs and Home Manager revisions.
nix/home.nix
Sets the Home Manager identity and state version.
nix/packages.nix
Lists shared packages and Linux-only packages.
setup.sh
Activates the correct profile and runs the remaining setup scripts.
bash_profile
Loads Home Manager variables and gives the Nix profile PATH precedence.

Bootstrap a machine

Install Nix first. Install Xcode Command Line Tools on macOS. Then clone this repository and run setup.

git clone --depth=1 https://github.com/nathantebbs/dotfiles
cd dotfiles
bash setup.sh

The script selects nathantebbs@macbook on macOS. It selects nathantebbs@linux on Linux. It activates packages before installing fonts or changing the login shell.

Git visibility Nix flakes only copy tracked files from a Git worktree. Stage a new Nix file before testing it. A commit is not required.

Daily use

Build before switching. This catches evaluation and package failures without changing the current profile.

activation_package="$(nix --extra-experimental-features 'nix-command flakes' \
  build '.#homeConfigurations."nathantebbs@macbook".activationPackage' \
  --no-link --print-out-paths)"

"$activation_package/activate"

setup.sh uses --no-link and runs the activation package directly. Use it when the other setup stages also need to run.

Update pinned inputs

nix --extra-experimental-features 'nix-command flakes' \
  flake update

nix --extra-experimental-features 'nix-command flakes' \
  flake check --no-build

Review the lock-file diff. Build the activation package before committing the update.

Change packages

Edit nix/packages.nix. Add portable tools to commonPackages. Add Linux compiler packages to linuxPackages.

commonPackages = with pkgs; [
  existing-tool
  new-tool
];

Search Nixpkgs when an attribute name differs from the command name. Build the macOS profile after every package change. Evaluate both profiles with nix flake check --no-build.

Project environments

The home profile is a workstation baseline. A project flake should own exact compiler versions, libraries, services, and build tools that vary by repository.

nix shell nixpkgs#package-name
nix develop
nix flake check

Use nix shell for a temporary command. Use nix develop when the project has a development shell. Keep a package global only when several unrelated projects or the dotfiles need it.

Rollback and recovery

Home Manager keeps generations. List them before changing the active profile. The rollback command activates the previous generation.

home-manager generations
home-manager switch --rollback

A Git revert is the repository rollback. Rebuild and activate after reverting a package or module change.

Broken login shell

Open a terminal with /bin/bash. Rebuild the profile. Then rerun the shell installer.

/bin/bash
bash util/scripts/install-bash.sh

Stale application environment

Applications opened before a package-manager migration can retain an old PATH. Quit and reopen the application. Restart the Emacs launch agent after plist or PATH changes.

emacsctl restart
emacsctl status

macOS boundary

Home Manager owns command-line packages and the user profile. macOS applications remain manual. This includes WezTerm, Ghostty, AeroSpace, Karabiner, Docker Desktop, and other applications that need vendor installers or macOS permissions.

The source-built Emacs application also remains outside Nix. Its launch agent receives ~/.nix-profile/bin through the committed plist. The current Emacs binary has no dynamic links into the removed Homebrew prefix.

Verification

Run these checks after a package update or bootstrap change.

nix --extra-experimental-features 'nix-command flakes' \
  flake check --no-build

nix --extra-experimental-features 'nix-command flakes' \
  build '.#homeConfigurations."nathantebbs@macbook".activationPackage' \
  --no-link

bash -n setup.sh bash_profile bashrc config.bash
plutil -lint emacs/dev.nathantebbs.emacs.plist

Open a clean login shell and inspect command ownership.

for command_name in bash git python3 go clangd nvim codex; do
  command -v "$command_name"
done

Each managed command should resolve below ~/.nix-profile/bin. A system tool is acceptable only when the package policy deliberately leaves it to the operating system.
