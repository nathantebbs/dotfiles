Dotfiles repository audit

2026-08-29dotfiles @ daee5d1Repository audit

The repository has good tool configs and a usable symlink deployer. Its installation contract is confused. Nix controls setup and leaks into runtime paths, while macOS and Linux ownership exists only inside shell branches. Keep shared configs at the root. Add macos/ and linux/ for system integration and overrides. Make setup deploy configuration only. Document dependencies without installing them.

Scope

I audited the tracked project configuration, setup scripts, shell files, editor entry points, OS integration, dependency declarations, README, and TODO history. I excluded .git/, third-party Emacs packages under .emacs.d/elpa/, font binaries, ignored runtime state, and existing generated notes. The audit did not assess the behavior of every editor plugin.

What is solid

Keep these parts

The shared editor configs already form useful units. The deployer is small and readable. Correct links are idempotent. Existing targets receive timestamped backups during normal replacement. All shell files pass bash -n. An isolated macOS deployment produced the expected links and passed a second run unchanged.

No tracked secrets, private keys, Emacs history, recent-file lists, autosaves, undo sessions, package directories, or native compilation caches were found. The personal name and email in gitconfig:2-3 fit a personal dotfiles repository.

Documentation drift

The README accurately describes the current Nix design. It no longer describes the desired ownership model. The main drift appears at README.md:8-10, README.md:33-45, README.md:58-70, and README.md:172-178. Those sections make Nix the dependency source and setup prerequisite. TODO.md:49-55 also records Homebrew as the Bash source, while live code uses Nix at util/scripts/install-bash.sh:22. The TODO is useful history, but it is not reliable operating documentation.

The replacement dependency section should group commands by shared core, macOS integration, Linux integration, and optional language tooling. Each entry should name the config that consumes it. It should not prescribe Homebrew, DNF, Nix, or another package manager.

Recommended direction

Decision

Keep OS-agnostic configs at the top level. Add OS directories only for files whose destination or content differs by platform. Do not add a generic shared/ directory. The root already communicates shared ownership.

setup.sh should select one OS and call a deployment-only script. The deployer should have a shared link table plus one OS link table. Shared shell startup should source macos/shell.bash or linux/shell.bash. WezTerm should keep shared appearance and pane behavior at the root. Its macOS key behavior should load from an OS file.

Dependencies should be data in the README, not actions in setup. Mark each dependency as required or optional. Name the feature that needs it. Missing optional tools should disable that feature without breaking shell startup or editor launch.

Recommended order of work

  • Split shell and WezTerm platform behavior. Remove all runtime references to ~/.nix-profile.
  • Create macos/ and linux/. Move OS integration files. Replace unconditional deployment with shared and OS link tables.
  • Reduce setup to deployment. Keep font and launcher helpers optional.
  • Remove flake.nix, flake.lock, and nix/.
  • Rewrite the dependency and installation sections. List consumers and optional features.
  • Make deployment replacement atomic. Protect the Emacsclient app target. Move Emacs runtime state outside the checkout.
  • Test fresh and repeated deployment with temporary homes for macOS and Linux. Run shell syntax checks after the migration.
